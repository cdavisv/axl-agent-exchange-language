# Experiment publication audit, 2026-11-18

This is a bounded audit of the available AXL experiment workspace and draft PR #1 at `a66e44cf102d248d0e2270d4a4306f158ed3ed1b`, not a claim to have inspected every computer or private chat. No production merge is implied.

## Covered by the draft branch before this audit

- Core codec and v2 compatibility; reference/delta/lifecycle profiles and synthetic comparisons.
- Cost-aware field sharing and trusted-session metadata amortization.
- Typed-row grammar, Llama/Gemma counts, frozen-corpus counterexamples, decoder overhead.
- Semantic enum/default negative result and bounded per-schema cache.
- Deferred-copy hardening, hybrid eager/lazy validation and shared-reference serialization reuse.
- Native-tool interoperability and abbreviated-instruction diagnostics, with strict runtime bounds and explicit model-unrun caveats.

The `native_tools` implementation is now registered in the runner. Its old local startup draft is not copied a second time: the published diagnostic preserves its candidates and rejected methods, and the final exported adapter was measured again.

## Missing evidence added by this audit

- [Codec switching](codec_switching/README.md): portable study, compact measured summaries, independent full-output verifier, and regression checks. Dynamic typed/JSON selection loses to the best static same-contract choice on both tested tokenizers at each reported horizon; the small conditional Qwen win over guarded JSON is retained. Full observation files are reproducibly generated rather than committed twice. Fresh Gemma reproduction against later core matches every recorded observation aggregate and selection count.
- [JTON comparator preflight](jton_preflight/README.md): ten original synthetic fixture groups, reproducible inventory and dated source-backed note. No JTON implementation, tokenizer comparison, speed or model experiment ran. A paper/specification discrepancy is a testing requirement, not a confirmed implementation bug. No third-party implementation is vendored.

## Rejected prototypes: do not restore as optimizations

1. Initial incremental-node-budget early rejection changed successful public helper return values (`validate_value` and `Schema.check`) from `None` to counts. On multiply-invalid payloads it also changed diagnostic precedence. Faster rejection of synthetic over-budget rows did not establish API compatibility. Keep rejected; the later published deferred-copy work has its own checks and is not evidence for shipping this initial prototype.
2. Fully lazy Python-value traversal reduced auxiliary allocation and over-budget rejection time but regressed ordinary tiny-object/record workloads by about 35%/22% in its local synthetic diagnostic. Its first version also had a late-binding generator bug caught by differential tests. Keep rejected as a wholesale replacement; the subsequent bounded hybrid validator is the separately tested published approach.
3. Smaller-looking instructions, schema specialization, semantic packing and adaptive format selection are not automatically better: startup/setup, exact data fidelity and equally capable JSON controls must remain in the comparison. Negative cases are part of the research record.

These rejected approaches are summarized rather than installed as callable alternate validators. Historical timing is machine/workload-specific, not inference or production throughput evidence.

## Remaining gaps

- Tokenizer counts are not model-generated validity, task success, retry cost, provider billing or inference latency. The shortened prompt has not been proven equally reliable; no default change is justified.
- Native JSON-tool definition is provider-neutral metadata, not a verified provider structured-output integration; wrapper overhead can reject near-limit otherwise-valid AXL messages.
- JTON reference implementation evaluation remains unrun.
- The older [v2 evidence studies](v2_evidence/README.md) are now archived separately with their frozen public corpus, Click BSD-3 notice and verified historical hashes. Eleven tests were rerun, but their complete historical tokenizer run was not rerun during packaging. They are not synthetic AXL3 data.
- No repository merge, deployment, private transcript, tokenizer/model weight or secret publication is part of this audit.
